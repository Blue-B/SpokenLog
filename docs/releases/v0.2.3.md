# SpokenLog 0.2.3, build 15

Adds in-app updates on Android and Windows. Earlier release files and tags are retained.

## New

- **In-app updates.** When SpokenLog opens, it checks GitHub for a newer release and offers to download it. The package is checked against the release's `SHA256SUMS.txt` before anything is installed; a file that does not match is deleted. A package that was already downloaded and verified is reused if the install is cancelled.
  - **Android:** the system install screen opens; tap Update. The first time, Android asks you to allow installs from SpokenLog.
  - **Windows (installed with Setup):** the installer runs silently and SpokenLog starts again. Copies run from the ZIP are not updated in place; download the new ZIP.
  - Recordings and transcripts are kept. Nothing is downloaded without asking, and the offer waits while a recording or transcription is running.
  - The checksum proves the download arrived intact; it comes from the same GitHub release, so it does not replace code signing. Windows binaries are still unsigned.
- **This version has to be installed by hand once.** 0.2.2 and earlier do not have the update check; from 0.2.3 on, newer versions are offered in the app.

## Fixes

- **Security: Android file import.** A file offered by another app's document provider could be saved outside SpokenLog's import folder by giving it a name such as `../../...`, overwriting app files. Imported files now keep only the last part of the name, and a path outside the import folder is refused. Found by a source security audit; there is no report of it being used.
- **Move to Trash from a recording's details** now closes the details and shows the confirmation, instead of leaving the trashed recording open.
- **iPhone builds** now include the Mobile Ads app ID that the linked ads SDK expects, so a future iOS build from this source does not stop at launch. iOS and macOS downloads remain at 0.1.3 until their next build.

## Verification

- Shared Flutter tests: 196 passed, four optional native-inference tests skipped. Apple packaging-tool tests passed. Static analysis: no errors or warnings.
- Android 15 emulator: a build labelled 0.2.1 found the published 0.2.2, downloaded and verified it, kept the progress window open when Back was pressed, opened the system installer and updated in place; after a cancelled install the retry reused the verified file. Updating 0.2.2 to this build kept recordings; recording, playback, import, trash and restore worked.
- A source security audit (standard profile) covered the updater, file import, the local AI connection (MCP), cloud keys, packaging and installers. Its one confirmed finding is fixed above; two open questions depend on facts outside the source (Windows code signing, and local port use by the AI connection while SpokenLog is closed).
- Windows 11: a Setup-installed build labelled 0.2.1 offered 0.2.2, downloaded and verified it, and the silent installer replaced it with 0.2.2. A silent install of this Setup starts SpokenLog afterwards.
- GitHub Actions built and tested the Windows and Android release targets from this source.

Not established for this release: a physical Android device, and iOS or macOS builds of this source.

## Distribution and device limits

Android still uses development signing, with the same key as earlier releases so it updates in place. Windows binaries are unsigned. macOS and iOS stay on 0.1.3 until their next build.
