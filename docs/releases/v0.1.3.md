# SpokenLog 0.1.3, build 11

**Unreleased candidate.** Download links continue to point to 0.1.2 until the release checks are complete. Existing 0.1.2 files and tags will be retained.

## Fixes

- Read WAV duration when importing a file and save it with the recording. Previously imported and legacy WAV files with missing duration now show their length when the library loads, without rewriting the existing audio or metadata. Other formats can still have unavailable duration.
- Let mobile navigation and library headers scroll away so recording cards remain reachable on small screens with large text. Preserve long-press range selection and edge scrolling.
- Make quick speech settings scrollable, including its Apply button, on short landscape screens. Allow the empty-transcript panel to grow with large text.
- Show a safe error message when secure storage rejects a settings write. Quick settings stay open and allow retry; raw error text, which may contain credentials, is not shown.
- Translate the observed English-interface gaps in automatic language detection, unnamed recording titles, playback controls and recording/import/export notices. This is not a claim that every message in the app has been translated.

## Verification so far

The shared-code test suite passed 173 tests. Four optional native-inference checks were skipped because their fixtures were not configured. Static analysis reported no errors or warnings and 18 existing informational findings.

Local Windows and Android test builds of the fixes were exercised before the version bump. Windows showed recovered durations for existing imports without changing their files. Android showed both old and new WAV durations and retained them after restart. At 360×640 logical pixels with 150% system text, the library could scroll its headers away and open a recording. At 640×360 with the same text setting, quick settings could scroll to Apply, and pressing it saved and dismissed the panel. These are execution checks of the fixes, not yet final-package verification for 0.1.3.

Secure-storage failure feedback and retry were checked with an injected `PlatformException` matching the observed macOS error. A fresh Mac execution check of the candidate is pending.

## Release gates still open

- Complete a real microphone speech recording, pause/resume, playback and transcription check. A completed WAV file alone is not proof that speech was captured correctly.
- Run the Mac candidate through settings, native import, local transcription and restart checks.
- Build and verify version 0.1.3/build 11 packages from one recorded source commit, including their identities, signatures and checksums.

Do not infer that these checks passed from this candidate document. Final results will be recorded before publication.

## Distribution and device limits

Android still uses development signing. Windows binaries are unsigned. The Mac app is ad-hoc signed and not Apple-notarized. The supplied iOS IPA remains unsigned and requires compatible signing and provisioning; it is not an App Store or TestFlight release and cannot be installed by tapping the file.

No iPhone/iPad or physical Android device is available in the current verification environment. Physical-device microphone quality, Bluetooth, screen-off/background recording, calls and interruption handling are not established by emulator or package checks. Cloud transcription uses the selected provider and can incur charges; this update does not establish a new live-provider verification result.
