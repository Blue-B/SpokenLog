# SpokenLog v0.1.0

The displayed version remains **0.1.0**. All four downloads now contain **build 5**, built from source commit `c4a7f97d1a6e6ce16db8f1f0b4405101fef494b4`. Android and Windows were built locally; macOS and iOS were built with the existing manual Codemagic workflow. GitHub Actions was not used because its account budget blocked jobs from starting.

## Build 5 fixes

- Cap temporary WAV upload parts at 24 MiB, including the header and complete audio frames. High-rate stereo imports no longer produce oversized Groq requests.
- Use actual WAV duration for Cloudflare chunk offsets, preserving trailing silence in timestamps.
- Stop the recorder when setup fails after microphone capture begins. Clear active-session state even when final metadata persistence fails.
- Create unique recording directories and reject overlapping starts, preventing rapid recordings from overwriting each other.
- Repair supported interrupted PCM WAV headers before recovery, retaining a `.recovery-original` copy. Do not recover a recording that is still active.
- Clean up prepared temporary files when splitting fails.
- Use the non-data-protection macOS Keychain option recommended by the storage plugin for distribution without a provisioning profile. This still uses Keychain, not plaintext files.

## Recording playback and transcription

- Recording details subscribe to player position, duration, play/pause state, and recording-data changes instead of displaying a stale snapshot.
- Progress uses the native playback position, including seeking, and a single-file recording uses the player's actual duration.
- Transcription progress, refreshed titles/transcripts, and errors remain visible inside the recording detail sheet.
- Missing Groq or Cloudflare credentials open an input dialog above the current recording. Cancel returns to the same recording; saving can continue the requested transcription.
- Repeated transcription taps do not stack credential dialogs or start duplicate requests. Credential storage failures stay in the dialog and do not display secret values.
- Large-text playback controls wrap instead of overflowing. Rename dialogs retain their input state safely through dismissal.

## Mobile navigation and settings

- The gear opens a settings hub with direct Groq API key, Cloudflare credentials, local-model management, transcription/audio-language, and display-language entries.
- Fixed All / Favorites / Collections / Trash scopes replace the growing horizontal collection-chip row.
- Collections open a vertical folder browser with explicit open/back/create/rename/delete controls.
- The calendar uses a compact month or week selector with a full-width selected-day agenda. Recording titles have two lines and transcript previews up to four lines; long Korean text is no longer squeezed into a one-character day-cell column.
- Changing the displayed month updates the selected date in that month.

## Local recognition and automatic language selection

- Moonshine KO remains a Korean-only engine, not a language detector. Selecting Auto requires explicit confirmation to transcribe that recording as Korean; the saved Auto preference is not silently changed.
- SenseVoice supports automatic detection within its supported languages. Local Whisper Tiny supports automatic detection, but explicit Cantonese (`yue`) is rejected because the bundled model lacks that language token.
- All three local engines check WAV input and reject unreadable, empty, malformed or unsupported audio before passing it to the native decoder.
- Android native libraries for arm64-v8a, armeabi-v7a and x86_64, and the iOS arm64 framework, were checked. Initial model downloads are required; local transcription does not accept imported MP3/M4A directly.

## Verification and limits

- **112 automated tests passed** locally. The Apple workflow also passed its shared-code analysis and regression-test stage. These include HomeScreen playback, credential-dialog, lifecycle and responsive-layout tests, plus fault fixtures for the build 5 fixes. Audio, HTTP and storage test services are controlled; these are not live cloud or microphone tests.
- The **12 new regression tests also passed on native Windows**, including interrupted-WAV repair and file replacement.
- Static analysis reported no errors or warnings; 18 pre-existing informational style/deprecation notices remain.
- Android release metadata, launcher identity, native libraries and APK signature were verified. The certificate SHA-256 matches the previous build 4 download.
- All archives passed CRC checks. Apple bundle identifiers, marketing/build versions, microphone permission and iOS background-audio configuration were checked. Download hashes match Codemagic's build report.
- The Windows ZIP was extracted separately and launched. The `SpokenLog` window rendered and remained responsive with product version `0.1.0+5`. Foreground-window restrictions prevented completing the planned import/playback interaction check; startup success is not an end-to-end recording result.
- Build tools: Flutter `3.47.5`; Windows Visual Studio Build Tools 2022; Codemagic Mac mini M2. Apple build ID: `6ab771de69d73073c078e350`.
- **Physical Android/iOS testing, macOS interactive testing, long/background microphone recording, model performance and live cloud transcription remain unverified.** Native Apple compilation and packaging are confirmed, not device behavior.
- Remaining hardening areas include cloud request timeouts, memory use for long local transcriptions, and atomic metadata/checkpoint writes. This refresh does not claim those risks are resolved.

## Android installation notice

Build 5 uses the same development signing certificate as the preceding repaired builds 3 and 4. Much older CI-built APKs used another certificate and may refuse an in-place update. Export/back up recordings and transcripts before considering removal of such an older installation, because uninstalling can delete local app data. Production/store signing is not configured.
