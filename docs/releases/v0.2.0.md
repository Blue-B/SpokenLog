# SpokenLog 0.2.0, build 12

Imports almost any audio or video file for local transcription, adds a read-only AI connection (MCP) on desktop, and makes model downloads survive dropped connections. Earlier release files and tags are retained.

## New

- **Any audio format.** M4A, MP3, AAC, FLAC, OGG, Opus, AMR, 3GP, WMA, AIFF, CAF, MP4, MOV, WebM and MKV imports are converted to 16 kHz mono WAV with the operating system's decoder (Android MediaCodec, Apple AVFoundation, Windows Media Foundation), so local transcription and speaker separation can use them. Which formats convert depends on the platform; a file that cannot be converted is kept as-is for cloud transcription. Recordings imported as non-WAV by earlier versions are converted the first time local transcription or speaker separation runs.
- **Recorder folders.** On Android the import picker opens in the Samsung Voice Recorder folder (`Recordings/Voice Recorder`) when it exists. On iPhone, share a recording from Voice Memos and choose SpokenLog.
- **AI connection (MCP), Windows and macOS.** Settings > AI connection lets Claude Code, Codex, pi and other MCP clients list, search and read transcripts. Read-only, `127.0.0.1` only, protected by a secret address. See the [AI connection guide](../mcp.md).
- **Local model management** is now its own screen for downloading and removing SenseVoice, Whisper (Tiny, Base, Small) and speaker-separation models. Choosing the engine stays in transcription settings.

## Fixes

- Model downloads resume from the received byte when the connection drops ("Connection closed while receiving data"), retrying up to five times and treating a 60-second stall as a drop. This applies to SenseVoice, Whisper and speaker-separation models.

## Verification

- Shared Flutter tests: 181 passed, four optional native-inference tests skipped. Static analysis: no errors or warnings, 18 existing informational findings. Apple packaging-tool tests: three passed.
- GitHub Actions built and tested the Windows and Android release targets from this source, including the new Windows Media Foundation decoder.
- The MCP server was exercised end to end with sample transcripts from Claude Code and Codex. Download resume was tested against a server that drops connections and against the live Hugging Face CDN with a Range request.

Not established for this release: decoding real M4A/MP3 files on a device, the Android and iPhone share/picker flows on a device, the macOS and iOS native decoders at runtime, and the desktop AI connection screen in a running app. Treat these as untested until confirmed.

## Distribution and device limits

Android still uses development signing, with the same key as earlier releases so it updates in place. Windows binaries are unsigned. Apple packages, when attached, are ad-hoc signed (macOS, not notarized) or unsigned (iOS, re-signing required). No physical iPhone/iPad or Android device was available in the verification environment.
